Evidence page · Version 1.5.0 · October 23, 2026

A feedback-selected setting, tested on unseen full hands.

This test compares two configurations of a new full-hand heuristic against one seeded novice opponent. It does not compare the original uninformed learner with a continuously trained successor. It does not isolate a performance benefit caused by RuVector.

What was tested?

The experiment ran on RuOS at 1:48 PM Eastern on October 23, 2026. It used a heads-up, play-money no-limit Hold’em engine covering preflop, flop, turn and river, with fresh 100-big-blind stacks for each hand.

A heuristic makes decisions using sampled equity and pot odds. Five predefined configurations adjust aggression threshold, call margin and bet size. Each configuration played 64 training seeds from both seats: 128 hands per setting, 640 training hands in total. The highest-mean setting was selected and frozen before testing.

The frozen default and selected setting were then tested on 256 separate seeds from both seats: 512 hands per policy, or 1,024 holdout hands in total. Training and test seeds do not overlap. Seeds make the runs reproducible; playing from both seats swaps the positions.

What changed?

The default averaged 4.64746 big blinds per hand. The selected configuration averaged 7.46777. The paired difference was +2.82031, with a normal-approximation 95% interval of [+1.14400, +4.49662], calculated across the 256 paired seed clusters.

A big blind is the compulsory starting stake. Here it is a simulated-chip unit, not money. Higher average profit is better. The interval describes sampling uncertainty in this single test setup; it does not establish strength against other opponents.

An independent Python calculation reproduced the training selection, test means, paired difference, interval, and train/test separation from the saved raw results.

What learned, and what did RVF do?

The explicit feedback-selection code chose aggression threshold 0.60, call margin 0.12 and pot fraction 0.90. This is bounded offline parameter calibration, not a neural self-play learner or mastery of the ten poker abilities.

The native RVF database accepted 641 vectors: 640 training experiences and a selected-policy marker. It was closed and reopened. The exact marker selected-policy-3 was retrieved at distance zero; the corresponding configuration was used in an actual engine decision. A second independent command reopened the file on RuOS and reproduced the lookup.

RVF persists and retrieves the experience and policy marker. The selection code performs the optimisation. A conventional lookup of the same configuration could produce the same action. An independent performance benefit from vector retrieval has not been measured.

Limits that matter

  • One seeded novice opponent, rather than a field of competitive players.
  • Five fixed candidate settings, 60 equity rollouts per decision, and fresh stacks each hand.
  • One training selection and one holdout set; no independent training replicates.
  • No claim of GTO play, tournament ability, live opponent adaptation, or improvement across all ten attributes.
  • The playable browser demo still uses its default configuration. It does not load this experiment’s selected setting.
  • Adapting rUv’s poker-darwin into the running full-game policy remains unfinished.
